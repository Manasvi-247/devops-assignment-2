# Repository rules

## Commits

**Never add attribution trailers.** No `Co-Authored-By: Claude`, no
`🤖 Generated with Claude Code`, no "Generated by", no emoji sign-off, no tool
attribution of any kind. The commit message ends with the last line of its own
body. This applies to commits, amends, rebases, squashes, PR descriptions and
issue comments.

**Use Conventional Commits** for every commit message:

```
<type>(<scope>): <subject>

<body>

<footer>
```

- `type`: one of `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`,
  `build`, `ci`, `chore`, `revert`
- `scope`: optional, lowercase, the area touched (e.g. `clusterip`, `nodeport`,
  `ci`). For this repo the assignment folder name is a good scope.
- `subject`: imperative mood ("add", not "added"/"adds"), lowercase first
  letter, no trailing period, 72 characters max.
- `body`: optional, wrapped at 72 columns, explains *why* rather than *what*.
- Breaking change: either `feat!:` / `feat(scope)!:` or a
  `BREAKING CHANGE: <description>` footer.

Good:

```
docs(clusterip): add service verification output
feat(nodeport): add nodeport service manifests
fix(clusterip): correct targetPort to match container port
chore: add gitignore for local kube output
```

Bad:

```
Updated files                        # no type, past tense, vague
docs: Added README.                  # capitalised, past tense, trailing period
feat(clusterip): add manifests

Co-Authored-By: Claude <noreply@anthropic.com>     # forbidden trailer
```

**One logical change per commit.** Don't bundle unrelated work. Never use
`git add .` blindly. Stage the specific paths that belong to the change.

## Writing

**No em dashes** (—) in commit messages, README files, documentation or code
comments. Use a comma, a full stop, a colon or brackets instead. Same goes for
en dashes used as punctuation.

Write plainly. Short sentences, normal words, no marketing tone.

## Things to ask before doing

- force-pushing, rewriting published history, deleting branches
- `git reset --hard`, discarding uncommitted work
- anything that talks to the remote beyond `push` to the current branch
